Its on-chain Python source was compared byte-for-byte with the [pushed source at commit ce25e284](https://github.com/Demigodd00/changeorder-firewall/blob/ce25e284b0878819a8744d33d72ad3006cd7f333/contracts/changeorder_firewall.py) (Git blob `845d5613b8081ce520c39310e69a0c88a8ce97c9`). The [public app](https://changeorder-firewall-studionet.esuspsychic.chatgpt.site/) preloads this order for wallet-free inspection. Its [proof manifest](../deploy/proof.json) records every finalized hash, leader result, validator-vote map, state snapshot and credited child transfer. `cd web; pnpm verify:proof` independently re-queries StudioNet without private keys.

Three obligations screened `OBSERVABLE`; buyer funding reserved exactly 0.003 test GEN; the supplier accepted; and the buyer approved all three generation-0 terms. The buyer proposed new T1 wording omitting `quantity` and `price`, the supplier countersigned, and validators [judged it `MATERIAL`](https://explorer-studio.genlayer.com/tx/0x9c4a9783167b67df1cba06af30ee5e63d59dd4396c3c5f4c95d836212e25cd23). The supplier's [stale T1 claim](https://explorer-studio.genlayer.com/tx/0xab2b0cd728bd66c5251bdc8a51848bfcc14185ee8a56b813c8b456bce8330faf) finalized with an expected execution error and no state change. The independent [T2 claim](https://explorer-studio.genlayer.com/tx/0xc55bf8718f0de7fab1230e66711a9912d971007239d2ee03245cd0336510d38f) succeeded without reapproval. The external child is verified by finality, `value_credited`, amount, recipient and parent hash; it is not misrepresented as an Intelligent Contract leader-execution receipt.

## Settled-term race fix

The latest source rechecks edited-term settlement before accepting a second signature and defensively aborts if an edited term somehow settles during review. [Two direct regression tests](SETTLED_TERM_GUARD.md) cover claim and refund before countersignature. This race is not claimed as a live StudioNet adversarial receipt. Likewise, typo-only, vague, and prompt-injection cases have local test coverage but not separate live receipts.

A test supplier signed screening, acceptance, claim and withdrawal through a script. Its [manifest](../deploy/browser-wallet-proof.json) and `cd web; pnpm verify:browser-proof` verify receipts, payout and code against that deployment's pinned *historical* source. This is not evidence of browser writes on the latest contract.

## Limits

These are test-only wallets and test GEN. The primary run proves this recorded material-change and payout case, not arbitrary model consistency, physical delivery, real supplier identity, or production security. Buyer-side latest-version browser writes, supplier browser signing and mobile-wallet QR pairing remain unverified. Portal acceptance or a point award is not guaranteed.
