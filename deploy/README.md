# Live StudioNet operations

`node web/scripts/live.mjs init` creates two **test-only** local wallets and prints their public addresses and balances. Their private keys stay in ignored `deploy/.wallets.json`; never commit, publish, reuse, or fund them with real assets. Back up that file before trying a funded demo. Losing it means losing the ability to countersign, approve, or claim in the demo.

`node web/scripts/live.mjs deploy` checks that the contract's working bytes equal the pushed Git blob, saves the deployment transaction hash immediately to ignored `deploy/.live-journal.json`, waits for finality and execution success, and saves the contract address and finalized initial read. Re-run the same command to resume a pending deployment rather than submitting a duplicate.

The runner probe is in `tests/integration/test_runner_probe.py`. It is intentionally small and uses a disposable auto-generated account. A passing probe does not prove the full project's LLM consensus or payable claims.

The latest live demo has completed. It used the ignored `deploy/.live-journal-v2.json`, selected by setting `CHANGEORDER_LIVE_JOURNAL=deploy/.live-journal-v2.json` for each `live.mjs` and `export-proof.mjs` invocation. `screen`, `activate`, `amend`, and `settle` resume from saved hashes. Do not delete the ignored journal or test-wallet file while reproducing these checks. The exporter validates saved results and regenerates `deploy/proof.json` and the frontend's `web/public/proof.json`; it never reads private keys. The public-safe manifest is a record of this specific test-only order, not a general security guarantee.

For an independent, **read-only** check against StudioNet, run `cd web; pnpm verify:proof`. This checks the deployed Python bytes against the pinned Git blob, finalized IC status and leader execution, validator votes, exact external transfer, and final contract state. `pnpm verify:proof -- --refresh-votes` updates public receipt metadata in both manifest copies; ordinary verification makes no file changes. The payout child is an external value transfer and has no IC leader receipt, so it is validated by credited value, recipient, parent transaction and finality instead.

The separate historical [`browser-wallet-proof.json`](browser-wallet-proof.json) records the October 20 buyer MetaMask test on earlier contract code. Run `cd web; pnpm verify:browser-proof` to recheck its finalized deploy, exact payable fund, buyer approval, script-signed supplier actions, external payout, pinned historical source bytes and final state. This verifier is read-only and does not use private keys. The recorded historical balance delta is cross-checked arithmetically against the payout receipt; a present-day account balance is not a historical balance proof. Latest-version browser writes, supplier browser signing and mobile pairing remain outside this test.
